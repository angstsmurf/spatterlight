# RE-DERIVED 2026-08-24 for the dead-NPC port (battle death is permanent).
# The old 505-turn route sold the deer carcass FIFTEEN times and searched two
# bandit corpses; it could only do that because Scarier used to let a
# battle-killed NPC keep walking, so the Bandit and the Deer respawned on
# every lap of their patrol.  The real Runner does not: killchar (run390
# @42D410, run400 @44B13C) runs the NPC's KilledTask and then unconditionally
# stamps room = &HFB (= -5, LitI2_Byte sign-extended) into the NPC record, and
# the walk ticker breaks out of the walk loop for any NPC sitting at -5
# (run390 loc_45A4BC -> loc_45ABD0; run400 loc_4685B6 -> loc_468D61).  The
# ADRIFT 4 manual says the same in prose: "The default behaviour for when a
# character is killed (i.e. its stamina reaches zero) is for the character to
# disappear, and any objects it was holding are moved to the current room."
#
# So Azra's designed economy is a GAME bug, not an engine one.  Both
# #banditkristdies (task 19) and #deerdies (task 37) move their NPC to hidden
# and hand back stamina, plainly expecting the walk to bring it round again --
# and it never did in the real Runner.  The author's intro remark ("you can
# continue to kill more bandits and sell more carcasses") is untested.
#
