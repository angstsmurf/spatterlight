# WHY 90 IS NOT REACHABLE BY ANYONE
#
# The file holds exactly ten `ACT type=4` awards summing to 90:

# Three of those are GENDER TWINS -- T10/T11, T24/T25, T74/T75 -- and the game
# asks you to pick male or female on the first move (VAR 1 [gender], room 10).
# So no single playthrough can bank more than 60 whatever it does; 90 is the
# sum of two mutually exclusive careers.  Of the 60, thirty more are behind
# three separate dead ends:
#
#  (1) THE FEMALE HALF OF THE GAME IS BROKEN.  T24 (`#12 release pressure (f)`)
#      is `where=0` -- ROOMLIST_NO_ROOMS, which `task_where_allows_run()` in
#      sctasks.cpp answers with a flat `return FALSE`, i.e. the task is
#      runnable NOWHERE.  Worse, T75 (the female torch, +10) has no `ACT
#      type=0` at all where T74 has `ACT type=0 v1=13 v2=0 v3=21` -- the male
#      torch drops the King of Spades into the Gnarled Woods and the female
#      one does not -- and `EXIT room=20 N -> dest=19 gateTask=74 wantDone=1`
#      gates the woods' only way back on T74 SPECIFICALLY.  A female player who
#      walks into Terror can never walk out.  Play male.
#
#  (2) THE VALVE IN RAGE IS STOLEN, AND RAGE IS A ONE-WAY TRAP.  T22
#      (`#12 turn valve debris here`, where=1 room=9, restr=0, rep=1) and T25
#      (`#12 release pressure`, +10, where=1 room=9) carry the IDENTICAL four
#      patterns -- `* turn * valve *`, `* open * valve *`, `* release * valve *`,
#      `* use * valve *`.  `run_game_commands_common()` in scrunner.cpp scans
#      forward and the first match whose restrictions pass wins, so T22 -- which
#      has NO restrictions -- answers all four phrasings forever:
#
#          >open valve
#          Through much vain effort, you begin to realize that the valve will
#          not move with the debris in the way.
#
#      even with the debris removed and the pipe fittings mounted.  The author
#      clearly meant T22 as the "you haven't cleared the debris yet" failure
#      and simply put it at the wrong index; they got the same shape RIGHT one
#      task earlier, where T20 (mount pipe, restricted on T23 done) sits BEFORE
#      T21 (`#12 pipe fitting too hot`, unrestricted) and therefore wins.
#
#      Two more sibling pairs in this same room prove SCARE's forward order is
#      what the author was building against, not a divergence: T18 (`remove
#      debris`, restricted on holding the mast) sits before T19 (`remove
#      debris` bare-handed, `ACT type=6 v1=2` -- INSTANT DEATH), and T20 before
#      T21.  Under any other order the Reservoir would kill every player on
#      sight and the author's own hint text ("First, close the valve to stop
#      the release of steam.  Then, attach the pipe fittings") would be a lie.
#      Under forward order that hint works and the T25 hint ("Make sure you've
#      cleared the debris and mounted the pipe fittings.  Then, open the
#      valve") is the one that is a lie.  It is an off-by-one in the task list,
#      not an engine question.  (Not cross-checked against a real run390.exe;
#      it costs 10 points inside a room you can never leave, so it cannot
#      change the verdict either way.)

#      And it CANNOT be walked off: `EXIT room=9 N -> dest=7 gateTask=25
